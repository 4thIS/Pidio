# Pidio — 라즈베리파이 원격 관리 미디어 플레이어 설계 문서

- **작성일:** 2026-07-16 (개정 2판)
- **상태:** 설계 브레인스토밍 반영본. 사용자 최종 검토 → 수정사항 반영 후 구현 계획(writing-plans)으로 진행 예정.
- **용도:** 학교 TV에 연결하는 라즈베리파이 기반 미디어 플레이어. 특정 교직원이 PC 웹으로 원격 관리(선택 재생, 반복/셔플, 사진·음악·동영상 혼합 플레이리스트, 예약 재생, 원격 업로드).

> **개정 2판 주요 변경:** ① 하드웨어 RPi4 → **RPi5**(원활한 4K) ② **Tailscale 삭제, 교내 LAN 전용** ③ **예약 재생**(날짜구간형/반복시간대형) 추가 ④ **사진·음악** 미디어 추가 + **음악 라인 편집** 모델 ⑤ **넷플릭스식 호버 미리보기** ⑥ 프론트 **Vue 3 + Vite** 확정.

---

## 1. 목표와 범위

### 1.1 핵심 목표
PC를 TV에 연결하고 USB로 영상을 옮기던 방식을 라즈베리파이로 대체해 **원격 웹으로 관리되는 미디어 플레이어**를 만든다. 편의성 중심:
- 웹에서 **선택 재생**, 멜론식 재생 큐 + 반복(순차1회/전체반복/한개반복) + **셔플**
- **동영상·사진·음악을 섞은 플레이리스트** (사진 슬라이드쇼 + 배경음악)
- **예약 재생** — 특정 기간/특정 요일·시간대에 지정 플레이리스트 자동 재생
- 드래그&드롭 **원격 업로드**, 썸네일, 제목 수정, **넷플릭스식 호버 미리보기**
- **부팅/스케줄 자동 재생**

### 1.2 확정된 컨텍스트
- **사용 환경:** 학교. 특정 교직원만 관리(공용 비밀번호 1개).
- **접속:** **교내 LAN 전용**(`http://<pi-ip>:포트`). 교외 접속 불필요 → Tailscale/Cloudflare 등 원격 터널 미사용.
- **TV 화면 역할:** 순수 재생 전용. TV엔 메뉴 UI 없음, 모든 조작은 PC 웹. "웹이 리모컨".
- **관리 화면 기준:** **PC**(넓은 화면). 모바일 대응은 부차적.
- **규모:** 콘텐츠 수십 개 수준.

### 1.3 비목표(YAGNI — 이번 범위 제외)
- TV 자체에서의 리모컨/키보드 조작
- 계정별 로그인·사용자별 이력 추적(공용 비번 1개로 충분)
- 다중 플레이어(여러 대) 중앙 관리
- 서버측 트랜스코딩(자동 코덱 변환) — 원본 재생만
- 교외 원격 접속

## 2. 하드웨어 / 플랫폼

- **기기:** Raspberry Pi 5. (원활한 4K 재생을 위해 RPi4 대신 RPi5 사용.)
- **재생 성능:** 4K 지원. HEVC(H.265) 4Kp60은 하드웨어 디코딩. H.264 4K는 CPU 디코딩으로 처리(일반적 콘텐츠 무난). 1080p는 여유.
- **OS:** Raspberry Pi OS (Bookworm, 64-bit).
- **저장 구성:**
  - **SD카드:** OS + 애플리케이션 + SQLite DB + 빌드된 프론트 정적 파일.
  - **USB 드라이브(탈착식):** 미디어 원본 + 썸네일 캐시. 마운트 지점 예: `/media/usb`.
    ```
    /media/usb/
      videos/      # 동영상 원본
      pictures/    # 사진 원본
      music/       # 음악 원본
      .pidio/
        thumbs/    # 생성된 썸네일 캐시 (동영상·사진)
    ```
  - USB를 빼서 PC에서 파일을 넣고 다시 꽂아도 정상 동작해야 함(핵심 제약).
- **재생 엔진:** mpv (IPC 소켓 제어). omxplayer는 폐기되어 미사용.
- **자동 시작:** systemd 서비스.

### 3.1 컴포넌트 (단일 책임)

1. **pidio-mpv-video (systemd 서비스)** — 화면 채널. mpv를 idle로 상주, IPC 소켓 노출. 동영상/사진 표시 + 대기 이미지. `Restart=always`.
2. **pidio-mpv-music (systemd 서비스)** — 음악 채널. 별도 mpv 인스턴스(오디오 전용), IPC 소켓 노출. 사진 슬라이드쇼 배경음악·음악 재생. `Restart=always`.
   - *두 인스턴스로 분리하는 이유:* 사진 슬라이드쇼(화면)와 배경음악(오디오)을 동시에 독립 제어하기 위함(5장 재생 모델 참조).
3. **pidio-web (systemd 서비스, FastAPI/Uvicorn)** — 애플리케이션 두뇌. 내부 모듈:
   - **API/UI 계층:** Vue 빌드 정적 파일 서빙 + JSON API + SSE(상태 푸시). 세션 인증(공용 비번).
   - **라이브러리 스캐너:** USB 폴더(videos/pictures/music) 스캔으로 현재 미디어 목록 산출. USB 마운트/언마운트 감지.
   - **메타데이터 스토어(SQLite):** 커스텀 제목·썸네일·길이·재생시간·플레이리스트·예약·설정.
   - **썸네일러:** 신규 파일 감지 시 백그라운드로 ffmpeg 썸네일·ffprobe 길이 취득.
   - **미디어 스트리머:** 호버 미리보기·재생용으로 원본 파일을 HTTP Range로 스트리밍.
   - **재생/스케줄 제어기:** 재생 상태·예약 판정을 소유하고 두 mpv 인스턴스를 IPC로 제어. mpv 이벤트 수신 후 다음 진행.
   - `Restart=always`.
4. **USB 드라이브:** 미디어 원본 + 썸네일 캐시. 탈착 가능(썸네일도 USB 동봉).
5. **SQLite (SD카드):** 메타데이터. USB를 빼도 남고, 파일 복귀 시 `content_id`로 재매칭.

### 3.2 프로세스 분리 원칙
화면 mpv / 음악 mpv / 웹을 **별도 systemd 서비스**로 분리 → 한쪽이 죽어도 다른 쪽 유지. 상시 켜져 있는 재생 기기의 견고성 확보.

## 4. 데이터 모델

### 4.1 파일 식별자 — 내용 기반 부분 해시 (`content_id`)
경로/파일명 기반은 PC에서 이름 변경·이동 시 메타데이터가 끊김. 따라서 **`파일크기 + 앞 1MB·뒤 1MB의 해시`** 조합을 `content_id`로 사용. 이름 변경·USB 내 위치 이동에도 같은 파일로 재인식 → 커스텀 제목·썸네일·예약 참조 유지. 수십 개 규모라 해시 비용은 무시할 수준. 모든 미디어 타입(동영상/사진/음악)에 공통 적용.

### 4.2 SQLite 스키마

```sql
-- 모든 미디어의 부가정보 (파일 자체는 USB가 진실)
CREATE TABLE media (
  content_id     TEXT PRIMARY KEY,   -- size + 앞/뒤 1MB 해시
  media_type     TEXT NOT NULL,      -- 'video' | 'photo' | 'music'
  original_name  TEXT NOT NULL,      -- 최초 발견 시 파일명
  custom_title   TEXT,               -- 사용자 수정 제목 (없으면 파일명 표시)
  rel_path       TEXT,               -- 현재 USB 내 상대경로 (스캔 시 갱신)
  duration       REAL,               -- video/music 재생시간(초); photo는 NULL
  default_photo_sec REAL,            -- photo 기본 표시 시간(초), 기본 5
  thumb_rel      TEXT,               -- .pidio/thumbs/<content_id>.jpg (video/photo)
  available      INTEGER DEFAULT 1,  -- 현재 스캔에 존재? (USB 빼면 0)
  first_seen     TEXT,
  last_seen      TEXT
);

-- 플레이리스트 (블록들의 순서 있는 모음)
CREATE TABLE playlists (
  id          INTEGER PRIMARY KEY,
  name        TEXT NOT NULL,
  repeat_mode TEXT DEFAULT 'off',    -- 'off'(순차1회) | 'all' | 'one'  ※ 블록 단위
  shuffle     INTEGER DEFAULT 0,     -- 블록 순서 셔플
  created_at  TEXT, updated_at TEXT
);

-- 플레이리스트 안의 "블록" = 재생 단위
--   kind='video'     : 동영상 1개(자체 소리, 음악 불가)
--   kind='slideshow' : 사진 슬라이드쇼 + 선택적 배경음악(=음악 라인)
CREATE TABLE playlist_blocks (
  id          INTEGER PRIMARY KEY,
  playlist_id INTEGER REFERENCES playlists(id) ON DELETE CASCADE,
  position    INTEGER,               -- 블록 순서
  kind        TEXT NOT NULL,         -- 'video' | 'slideshow'
  video_id    TEXT REFERENCES media(content_id),  -- kind='video'일 때
  music_id    TEXT REFERENCES media(content_id)   -- kind='slideshow'의 배경음악(NULL=음악없음)
);

-- 슬라이드쇼 블록(음악 라인) 안의 사진들
CREATE TABLE block_photos (
  block_id    INTEGER REFERENCES playlist_blocks(id) ON DELETE CASCADE,
  position    INTEGER,               -- 라인 내 사진 순서
  photo_id    TEXT REFERENCES media(content_id),
  duration_sec REAL,                 -- 이 사진 표시 시간(초). NULL이면 media.default_photo_sec
  PRIMARY KEY (block_id, position)
);

-- 예약(스케줄)
CREATE TABLE schedules (
  id          INTEGER PRIMARY KEY,
  playlist_id INTEGER REFERENCES playlists(id) ON DELETE CASCADE,
  sched_type  TEXT NOT NULL,         -- 'date_range' | 'weekly'
  -- date_range형:
  start_dt    TEXT,                  -- 'YYYY-MM-DD HH:MM'
  end_dt      TEXT,
  -- weekly형:
  weekdays    TEXT,                  -- 예 'mon,tue,wed,thu,fri'
  start_time  TEXT,                  -- 'HH:MM'
  end_time    TEXT,
  enabled     INTEGER DEFAULT 1
);

-- 전역 설정 (key-value)
CREATE TABLE settings ( key TEXT PRIMARY KEY, value TEXT );
```

**settings 주요 키(예):**
- `password_hash` — 공용 비밀번호 해시.
- `default_playlist_id` — **기본 재생목록**(활성 스케줄이 없을 때 재생, 부팅 자동재생 겸함). 없으면 대기화면.
- `standby_image_path` — 대기화면 이미지 경로.

### 4.3 동작 규칙
- **스캔 시:** 파일마다 `content_id` 계산 → 있으면 `rel_path`/`last_seen`/`available=1` 갱신, 없으면 신규 `media` 행 삽입 + (video/photo)썸네일·(video/music)길이 생성.
- **USB 뺄 때:** 스캔에 없는 행은 `available=0`(삭제 아님 → 메타·플레이리스트 참조 보존). 목록에 미표시.
- **플레이리스트의 없는 항목:** 참조 미디어가 `available=0`이면 UI에서 흐리게 표시, 재생 시 건너뜀.
- **즉석 선택 큐:** DB 저장 안 함 — 순수 런타임 상태(5장).

## 5. 재생 모델 & mpv 연동

### 5.1 재생 단위 = "블록"
재생 대상(큐/플레이리스트)은 **블록의 순서 있는 목록**이다. 블록은 둘 중 하나:
- **동영상 블록:** 동영상 1개. 화면 mpv가 재생(자체 소리 O). 음악 채널 정지.
- **슬라이드쇼 블록:** 사진들(각자 표시 시간) + 선택적 배경음악. 화면 mpv가 사진을 순서대로 표시(각 `image-display-duration`), 음악 mpv가 배경음악 재생. 음악이 사진보다 짧으면 루프, 길면 사진 종료 시 음악 정지. 블록 종료 조건 = 사진 시퀀스 종료.

> **⚠ 검토 필요(파생 결정):** 아래 반복/셔플의 "블록 단위" 의미는 새 미디어 모델에서 논리적으로 파생한 것으로, 사용자 검토 시 조정 가능.

### 5.2 큐 소스 (멜론식)
1. **전체 목록에서 즉석 선택** — 선택한 항목들로 임시 큐 구성(저장 안 함). 동영상=동영상 블록, 사진=슬라이드쇼 블록(음악 없음, 기본 표시시간), 음악=음악 블록(화면엔 음악 정보 화면).
2. **저장된 플레이리스트 로드** — 음악 라인 편집기로 만든 블록 구성을 큐로 로드.

### 5.3 런타임 재생 상태 (메모리 + 부팅용 스냅샷)
```
queue      : [block, ...]        # 현재 재생 큐(블록 목록)
current    : 블록 인덱스
repeat     : off | all | one     # 순차1회 / 전체반복 / 한개반복 (블록 단위)
shuffle    : bool                # 블록 순서 셔플(원본순서 별도 보관)
mode       : auto | manual       # 스케줄 자동 / 수동 오버라이드
status     : playing | paused | standby
```

### 5.4 웹 → 백엔드 명령
- `play_selection([ids])` · `load_playlist(id)`
- `next / prev / jump_to(i) / pause / resume / stop`
- `enqueue / remove / reorder`
- `set_repeat(mode) / set_shuffle(bool)`
- `resume_auto()` — 수동 모드 → 자동 모드 복귀

### 5.5 백엔드 → mpv IPC 매핑
| 동작 | 화면 mpv | 음악 mpv |
|---|---|---|
| 동영상 블록 | `loadfile <video> replace` | `stop` |
| 슬라이드쇼(사진) | 사진 순차 `loadfile`, `image-display-duration <초>` | 배경음악 `loadfile`(없으면 stop) |
| 음악 블록(즉석) | 음악 정보 화면 이미지 | `loadfile <music>` |
| 한 개만 반복 | 해당 블록 종료 시 재로드(사진 시퀀스/영상 loop) | 음악 loop |
| 대기화면 | `loadfile <standby.png>` (`image-display-duration inf`) | `stop` |
| 재생 끝 감지 | `end-file` 이벤트 → `advance()` | — |

### 5.6 `advance()` (블록 자연 종료 시)
- `repeat == one` → 현재 블록 반복.
- 그 외 → `current + 1`. 큐 끝을 넘으면: `all`이면 처음으로 순환(셔플이면 **새로 셔플**), `off`이면 정지 → 자동 모드면 스케줄 재평가, 아니면 대기화면.
- `shuffle` 켜짐이면 셔플된 블록 순서를 따르고, 끌 때 원본 순서로 복원.

### 5.7 실시간 UI 동기화 — SSE
백엔드가 현재 블록·진행위치·큐·모드를 소유하고 **SSE로 상태를 푸시**. 다중 접속 시 모두에게 동일 상태 반영.

## 6. 예약(스케줄) 시스템

### 6.1 예약 타입
플리 화면의 **[🕒 예약] 버튼** → 폼에서 토글로 타입 선택:
- **① 날짜 구간형(date_range):** 시작 `YYYY-MM-DD HH:MM` ~ 종료 `YYYY-MM-DD HH:MM`. 그 구간 동안 해당 플리 자동 재생. 예) `8/1 09:00 ~ 8/7 18:00 시험기간 플리`.
- **② 반복 시간대형(weekly):** 요일 다중선택(월~일 버튼) + `HH:MM ~ HH:MM`. 매주 해당 요일·시간대에 자동 재생. 예) `매주 월~금 12:00~13:00 점심 플리`.

### 6.2 우선순위 (겹칠 때)
**② 반복 시간대형 > ① 날짜 구간형.**
- 시험기간(종일)이 깔려 있어도 12–13시엔 점심 플리가 덮어씀. 시간대 종료 후 자동으로 날짜형 플리로 복귀.
- **같은 타입끼리는 겹침 금지** — 저장 시 겹치면 경고/거부. 서로 다른 타입은 위 우선순위로 자동 해결.

### 6.3 현재 재생 판정 (스케줄러)
매 순간(또는 분 단위 틱 + 경계 이벤트) "활성 예약 중 최우선"을 계산 →
- 활성 예약 있음 → 그 플레이리스트 재생.
- 활성 예약 없음 → **기본 재생목록**(`default_playlist_id`) 있으면 재생, 없으면 대기화면.
- 부팅 시에도 동일 판정으로 자동 재생 시작(부팅 자동재생 = 이 로직에 흡수).

### 6.4 수동 오버라이드
- 교직원이 수동 재생(선택재생/플리로드 등)하면 플레이어가 **전역 `manual` 모드**로 전환 → 스케줄 판정 전면 중지(수동 우선).
- UI의 **[자동 모드로 복귀]** 버튼을 누르면 `auto` 모드로 돌아가 그 시점 스케줄을 재평가·적용. (자동으로는 복귀하지 않음 — 예측 가능성 우선.)

### 6.5 예약 관리 UI
- 플리 헤더의 `🕒 예약됨/예약` 버튼. 설정 시 플리 상단에 **예약 요약 배너**(예: "매주 월~금 12:00~13:00 · 날짜형보다 우선").
- `✏ 예약 수정` → 현재값이 채워진 편집 팝업(토글로 타입 전환, 요일/시간·날짜 입력, **🗑 예약 삭제**, 취소/저장). 같은 시간대형과 겹치면 저장 시 경고.

## 7. 웹 UI (PC 기준, Vue 3 SPA)

> **시각 디자인 주의:** 아래는 정보 구조/배치 기준. 실제 시각 스타일(폰트·여백·카드·애니메이션)은 구현 단계에서 디자인 스킬(frontend-design / high-end-visual-design)로 별도 고급화한다.

### 7.1 메인 화면 (위 → 아래)
1. **지금 재생 중(최상단)** — 큰 썸네일 + 현재 항목 제목 + 출처(플리/전체, N/총개) + 진행바 + 컨트롤(⏮ ⏯ ⏭, 반복 3상태, 셔플). **수동 모드면 [자동 모드로 복귀] 버튼** 노출. SSE 실시간 갱신.
2. **플레이리스트(중단)** — 각 카드 = **내용물 썸네일 여러 장 겹침**(표지) + 이름·항목수·총시간 + ▶. 클릭 → 플리 상세 화면. `[＋새 목록]`. 가로 스크롤.
3. **전체 목록(하단)** — 동영상/사진/음악 목록(썸네일·제목·길이·타입). **체크박스 다중선택** → "선택재생/큐에 추가/플레이리스트로 저장". 개별: 바로재생·제목 인라인 수정·⋮. **넷플릭스식 호버 미리보기**(7.4).

### 7.2 플레이리스트 상세 화면 (통합)
한 화면에 모두 포함:
- **헤더:** 제목 + `▶재생` + `🔁전체반복`·`🔀셔플` 옵션 + `🕒예약` 버튼.
- **예약 요약 배너**(설정 시).
- **음악 라인 편집기(A방식):**
  - **🎬 동영상 블록** — 음악 라인 밖 독립 행(자체 소리, 음악 불가).
  - **🎵 음악 라인(슬라이드쇼 블록)** — 라인마다 배경음악 1개 + 사진들(각 표시시간). **사진을 드래그해 다른 음악 라인으로 이동**, 라인 내 순서도 드래그.
  - **🔇 음악 없음 라인** — 무음 슬라이드쇼.
  - `＋ 음악 라인 추가 · ＋ 동영상 추가 · ＋ 사진 추가`.
  - 드래그: `vuedraggable`(SortableJS).

### 7.3 재생 큐 패널
지금재생 출처 클릭/버튼으로 현재 큐 패널 → 블록 드래그 정렬·삭제·점프.

### 7.4 넷플릭스식 호버 미리보기
- **동영상:** 목록 항목에 마우스 호버 → 썸네일이 **부드럽게 살짝 커지며 그 자리에서 무음 재생**(처음부터). FastAPI가 원본을 HTTP Range 스트리밍, `<video>`가 재생. 호버 해제 시 원복.
- **사진:** 호버 → 큰 이미지 팝업.
- **음악:** 호버 → 정보(제목/길이) + 미리듣기(선택).

### 7.5 업로드
- 화면 아무 곳에 파일 드롭 → `/api/upload`. **대용량 대비 청크(분할) 업로드** + 진행률.
- 타입별로 USB `videos/`·`pictures/`·`music/`에 분류 저장(확장자/MIME 판별). 임시 이름으로 쓰고 완료 시 rename.
- USB 미마운트 시 거부 + 안내. 업로드 전 여유 용량 체크.

### 7.6 썸네일 & 메타 (백그라운드)
신규 파일 감지 → 백그라운드 태스크로 ffmpeg 썸네일(동영상 프레임/사진 축소) + ffprobe 길이(동영상·음악). 업로드 응답 즉시 반환, UI는 준비 전 플레이스홀더.

### 7.7 설정 뷰(⚙)
기본 재생목록 지정, 대기화면 이미지 업로드, 사진 기본 표시시간, 공용 비번 변경.

## 8. 인증 / 네트워크
- **인증:** 공용 비밀번호 1개. 로그인 성공 시 세션 쿠키. 해시는 `settings.password_hash`. 로그인 시도 rate limit.
- **네트워크:** **교내 LAN 전용.** `http://<pi-ip>:포트` 직접 접속. 원격 터널 없음.

## 9. 에러 처리 · 엣지케이스

| 상황 | 처리 |
|---|---|
| 부팅 시 USB 없음 | 대기화면 유지, "USB 대기". 마운트 감지 → 스캔 → 스케줄 재평가 자동재생 |
| 재생 중 USB 뽑힘 | 언마운트 감지 → 정지, 대기화면, "USB 분리됨" 배너. 목록 `available=0` |
| USB 재연결 | 자동 재스캔, `content_id` 재매칭으로 메타·플리·예약 참조 복원, SSE 갱신 |
| PC에서 삭제/이름변경 후 재연결 | 삭제→`available=0`(참조 흐리게, 재생 시 skip). 이름변경→`content_id` 동일 → 같은 미디어 인식 |
| 플레이리스트에 없는 미디어 | 재생 시 자동 skip, UI 흐리게 |
| 손상/미지원 코덱 | mpv `end-file` error → skip, "재생 실패" 표시 |
| 같은 타입 예약 시간 겹침 | 저장 시 경고/거부 |
| 슬라이드쇼 음악이 사진보다 짧음/김 | 짧으면 음악 loop, 길면 사진 종료 시 음악 정지 |
| 업로드 중 연결 끊김 | 청크 업로드로 재개. 미완성 임시파일은 정리 태스크가 청소 |
| 디스크 가득 참 | 업로드 전 용량 체크, 부족 시 거부 + 안내 |
| 화면/음악 mpv 죽음 | systemd `Restart=always`. 백엔드 소켓 재연결 후 상태 복구 |
| 웹 프로세스 죽음 | systemd 재기동. mpv는 계속 재생(분리). 재기동 후 스냅샷 복원 |
| 동시 접속(교직원 2명) | 상태 서버 단일 소유 → SSE로 모두 즉시 반영(공유) |
| 잘못된 비번 | 로그인 거부 + 시도 제한 |

**상태 지속성:** 런타임 재생상태(큐/current/repeat/shuffle/mode)를 주기적 JSON 스냅샷 저장 → 웹 재시작 시 복원.

## 10. 테스트 전략
- **단위 테스트:** `content_id` 계산(이름변경 후 동일성), `advance()` 상태머신(반복×셔플×큐끝), **스케줄러 우선순위 판정**(날짜형/시간대형 겹침·경계), 플레이리스트/블록/사진 CRUD·순서, 예약 겹침 검증, 메타 재매칭. → mpv/USB 없이 순수 로직, mpv IPC는 목(mock).
- **통합 테스트:** 가짜 mpv IPC 소켓 2개(화면/음악)로 명령 매핑·동시 제어 검증. USB 마운트/언마운트는 임시 디렉토리 시뮬레이션.

- 구현은 TDD(테스트 우선).
